# Chinese patch maintenance context

This fork's `zh-cn` default branch maintains an offline, reversible patch for official Bruno releases. Upstream application source is retained at the supported release tag. `main` remains the upstream tracking branch. Upstream workflows are preserved under `.github/upstream-workflows/`; only the Chinese patch workflow runs in this fork.

Runtime boundaries: archive.mjs reads/rebuilds ASAR without unpacking native modules; operations.mjs owns Windows backup and restore; mac.mjs stages and signs a full Mac app and preserves the original signature in a complete bundle backup; cli.mjs checks processes, version and platform. plans.json pins original archive and per-file hashes. Only reviewed static UI literals are changed, never user data, payloads, authentication semantics or license logic.

Update flow now runs in `.github/workflows/zh-update.yml`, scheduled daily at 02:17 UTC. `maintenance/prepare.py` checks stable official releases, preserves the maintained overlay while syncing upstream source, verifies both ZIP digests, generates plans and extends only new eligible UI text using a pinned offline translation model. Significant scope changes fail closed. PRs run full rehearsals without publishing. Native checks run via reusable `zh-ci.yml`. The privileged publisher executes trusted scheduler code, validates commit-bound evidence and ZIP/binary/remote digests, fast-forwards the branch without force, and publishes a verified draft. `rehearse` never publishes; `rebuild` permits a new revision of the current release. Monthly activity preserves public scheduled workflow eligibility. Do not weaken these gates to make a failed upstream version pass. Installation on a user's computer is separate from publishing a tested patch.

Validation map: test.mjs covers archive correctness and transactional safety; ci/smoke.cjs compares original and patched UI/request behavior; ci/verify.mjs exercises native apply, ad-hoc signing, repeated apply and complete restore on the actual target OS. macOS runners must report arm64. CI cannot certify Gatekeeper handling of downloaded/notarized files; communicate that separately.

No local profiles, credentials, installation backups, raw app logs or machine-specific paths may be committed. Artifacts contain only the compiled tool, public source, documentation and checksums.

Maintenance tests: `python -m unittest discover -s maintenance -p 'test_*.py'`. Cloud source synchronization must reject fork changes outside `tools/zh-cn`, `README.zh-CN-patch.md`, and the active/inactive workflow directories. GitHub Models is not used; no external inference credential is required. The offline model must remain pinned, weights-only loading must remain enabled, and translated data cannot introduce executable code. The previous local Codex heartbeat is retired after cloud acceptance.
